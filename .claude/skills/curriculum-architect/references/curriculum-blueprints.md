# Curriculum Blueprints

Five full module-to-lesson blueprint patterns, sequence heuristics, lesson type guide, and completion-marker menu. Load when designing or reviewing a full course structure.

---

## 1. The five blueprint patterns

Each pattern describes a different learning arc. Choose the pattern that best matches your course's purpose, then adapt the module structure to your specific content.

---

### Pattern 1: Linear Skill Build

**Best for:** Technical skills, professional processes, step-by-step methods (software tools, writing frameworks, financial modeling, design systems).

**Structure:** Each module builds directly on the previous. The student cannot do Module 3 without having completed Modules 1 and 2. The arc moves from foundational knowledge through practiced skill to applied competence.

**Module pattern:**
- Module 1: Foundations (the vocabulary, the mental model, the tools).
- Module 2: Core Skill A (the first primary technique, practiced in isolation).
- Module 3: Core Skill B (the second primary technique, practiced in isolation).
- Module 4: Integration (combining Skills A and B in a realistic scenario).
- Module 5: Application (using the full skill set on a real project or case).

**Sequence rule:** Every lesson in Module N can freely reference any lesson in Module N-1. No forward references allowed.

**Completion marker per module:** Module 1: a completed reference card or glossary. Module 2: a practice exercise output. Module 3: a second practice exercise output. Module 4: a combined-skill practice piece. Module 5: a finished deliverable (portfolio piece, template, or case study).

**Example structure:** A course on SQL for data analysts.
- Module 1: How databases and SQL work (vocab, structure, mental model).
- Module 2: Querying single tables (SELECT, WHERE, ORDER BY).
- Module 3: Aggregating data (GROUP BY, HAVING, aggregate functions).
- Module 4: Joining tables (INNER, LEFT, RIGHT joins with practice data sets).
- Module 5: Building a real report from a messy database.

---

### Pattern 2: Project-Based

**Best for:** Creative skills, portfolio building, product creation (design, writing, photography, building a website, developing a product).

**Structure:** The entire course is oriented around producing one finished project. Each module adds a layer or phase to that project. The student finishes with a real artifact.

**Module pattern:**
- Module 1: Planning and scoping the project (what we're building and why).
- Module 2: First layer (the foundation of the project).
- Module 3: Second layer (building on the foundation).
- Module 4: Third layer (refining and extending).
- Module 5: Finishing and sharing (polishing, publishing, presenting, or pitching).

**Sequence rule:** Each module produces a draft or component that feeds directly into the next module. The project grows visibly.

**Completion marker per module:** Each module ends with a saved draft, a completed component, or a decision documented in the project plan. The final module ends with the finished project.

**Example structure:** A course on building a personal brand website.
- Module 1: Positioning and strategy (define your message and target audience).
- Module 2: Copywriting your pages (homepage, about, services).
- Module 3: Designing the site (layout, visual identity, responsiveness).
- Module 4: Content and proof (portfolio, testimonials, case studies).
- Module 5: Launch and promote (publish, share, drive traffic to key pages).

---

### Pattern 3: Problem-Solution

**Best for:** Practical problem-solving, troubleshooting, business improvement (negotiation, parenting, sales, health behavior change, conflict resolution).

**Structure:** Each module addresses one distinct problem the audience faces. The modules do not need to be strictly sequential; a student could jump to the module most relevant to their current situation. The course has a natural beginning and end but allows flexible navigation.

**Module pattern:**
- Module 1: Frame the problem set (why these problems exist and how they relate).
- Module 2: Problem A (what it is, why it happens, how to solve it, practice).
- Module 3: Problem B.
- Module 4: Problem C.
- Module 5: Integration (how to apply the solutions together in a realistic scenario).

**Sequence rule:** Module 1 is always first. Modules 2 through N-1 can be consumed in any order. The final module is always last.

**Completion marker per module:** Module 1: a completed self-assessment identifying which problems are most pressing. Each problem module: a decision made or a tool applied. Final module: a personal action plan.

**Example structure:** A course on difficult workplace conversations.
- Module 1: Why these conversations feel hard (psychology, stakes, common avoidances).
- Module 2: Giving critical feedback (structure, delivery, response handling).
- Module 3: Pushing back on a decision without damaging the relationship.
- Module 4: Addressing a colleague's performance issue peer-to-peer.
- Module 5: Building a practice habit for ongoing difficult conversations.

---

### Pattern 4: Habit Formation / Behavior Change

**Best for:** Lifestyle change, productivity, health, creative practice, personal development (writing daily, exercising consistently, building a practice, changing a mindset).

**Structure:** The course builds the student's system, habit, and resilience over time. It front-loads the "why" and spends most of its energy on "how to make this stick" rather than just "how to do this."

**Module pattern:**
- Module 1: The case for change (identity, motivation, what makes habits fail).
- Module 2: The smallest viable version (start here; succeed quickly; build confidence).
- Module 3: Building consistency (systems, cues, tracking, troubleshooting resistance).
- Module 4: Expanding the habit (adding complexity, deepening the practice, handling plateaus).
- Module 5: Protecting the habit long-term (relapse planning, social support, re-entry after breaks).

**Sequence rule:** Strictly sequential. The habit must be established at each stage before the next is introduced.

**Completion marker per module:** Module 1: a written "why" statement. Module 2: seven consecutive days of the minimal habit. Module 3: a completed system design (cue, routine, reward, tracker). Module 4: a milestone result. Module 5: a written relapse protocol.

**Example structure:** A course on building a daily writing practice.
- Module 1: Why you keep stopping (resistance, identity, what daily actually means).
- Module 2: The 10-minute minimum (start so small you cannot fail).
- Module 3: Systems that hold (when, where, what to write, tracking without obsessing).
- Module 4: Going deeper (longer sessions, quality goals, publishing your work).
- Module 5: Writing through life (travel, busy seasons, creative blocks, picking back up).

---

### Pattern 5: Professional Certification Style

**Best for:** Knowledge-heavy topics with a formal body of content (finance, law, medicine, project management, compliance, technical certifications).

**Structure:** Comprehensive coverage of a defined domain, with clear domains, sub-domains, and formal assessments. The course proves mastery through progressive testing, not just content consumption.

**Module pattern:**
- Module 1: Domain overview and mental model.
- Modules 2 through N: One domain or sub-domain each, with content, examples, and a quiz or assessment.
- Final module: Comprehensive review, capstone assessment, and application guidance.

**Sequence rule:** Domain modules can often be independent. Review module is always last.

**Completion marker per module:** Each module ends with a quiz, a graded exercise, or a case analysis. The final module ends with a capstone exam or project.

**Example structure:** A course on project management fundamentals.
- Module 1: The project management landscape (what a project is, key terms, common frameworks).
- Module 2: Initiation (charter, stakeholders, success criteria).
- Module 3: Planning (scope, schedule, budget, risk).
- Module 4: Execution (team management, communication, change control).
- Module 5: Monitoring and closing (status reporting, lessons learned, project handoff).
- Module 6: Capstone review and mock exam.

## 2. Sequence heuristics

Use these rules to review any curriculum before delivering it.

**Rule 1: Prerequisite order.** Scan every lesson for vocabulary or concepts introduced later in the outline. Move the introducing lesson earlier, or add a brief preview in an earlier lesson. A student should never encounter a term for the first time after it was assumed.

**Rule 2: The momentum curve.** Map the difficulty level of each lesson on a simple scale (1 = foundational, 3 = challenging). The curve should rise gradually, with small "rest" lessons (practice, review, or light synthesis) after each difficult cluster. A flat curve means the course is boring. A spike that jumps from 1 to 3 with no 2 in between means the student will feel lost.

**Rule 3: Concept-to-practice ratio.** Aim for a maximum of three consecutive concept lessons before a practice lesson. If a module is all concept, it will feel like a lecture and students will disengage.

**Rule 4: Completion markers.** Every module must end with something the student has done, not just watched. If the last lesson in a module is a concept lesson, add a short action step or exercise. Even a "complete this worksheet" or "write your answer to this question" counts.

**Rule 5: The 30-minute quick win.** The first quick, tangible result should appear within 30 minutes of starting the course. Place a practice or application lesson with a satisfying output early in Module 1 or at the beginning of Module 2.

**Rule 6: Module size consistency.** Modules should be roughly consistent in size (within one or two lessons of each other). A module with two lessons and one with eight lessons feel unbalanced. Either split the large module or combine the thin one with an adjacent module.

## 3. Lesson type guide

### Type 1: Concept lesson

**What it is:** Introduces a new idea, framework, or mental model.
**When to use it:** At the beginning of a new topic, before any application. This is how we give students the vocabulary and structure they need to make sense of what follows.
**Output:** The student leaves with a new mental model. No practice required in this lesson.
**Length:** 8-12 minutes.
**Risk:** Too many in a row creates passive learning. Limit runs of concept lessons to three maximum before adding a practice lesson.

### Type 2: Demonstration lesson

**What it is:** The creator performs the skill or process in real time while narrating decisions.
**When to use it:** After a concept lesson, when the skill has a visible performance the student can observe and imitate.
**Output:** The student has seen the skill done correctly and understands the decision points.
**Length:** 10-15 minutes. Longer demonstrations should be broken into two lessons.
**Risk:** Demonstrations can become passive if the student never pauses to try. Always follow a demonstration lesson with a practice lesson.

### Type 3: Worked example lesson

**What it is:** The creator walks through a complete, pre-built example case, explaining the decisions and showing the finished output.
**When to use it:** When there is a high risk of a student making a common error, or when the process has many interdependent steps that are easier to understand in a complete example than in abstract steps.
**Output:** The student has a model they can compare their own work against.
**Length:** 8-12 minutes.
**Risk:** Students may try to copy the example rather than understanding it. End the lesson with a question or variation exercise.

### Type 4: Practice lesson

**What it is:** The student does the work. The lesson provides a prompt, a scenario, a template, or a constraint, and the student produces output.
**When to use it:** After every one to three concept or demonstration lessons. Practice converts watching into doing.
**Output:** The student has a produced artifact (a draft, a completed worksheet, a decision, a plan).
**Length:** Varies. Instruction is 3-5 minutes; the work takes as long as it takes.
**Risk:** Too easy a practice prompt fails to build real skill. Too hard a prompt without enough setup causes frustration. Calibrate the prompt to the lesson sequence.

### Type 5: Synthesis lesson

**What it is:** Combines multiple previously taught skills into one integrated task or case.
**When to use it:** At the end of a module or at key integration points in the course. This is where the student builds confidence that they can use everything together, not just each skill in isolation.
**Output:** A complete artifact that demonstrates the full module's skills. This is the completion marker for the module.
**Length:** 10-20 minutes for instruction; the work product may take longer.
**Risk:** If the student is not ready for synthesis, this lesson will feel overwhelming. Confirm the prerequisite lessons are strong before the synthesis lesson.

## 4. Completion-marker menu

Every module needs at least one completion marker from this list.

| Marker type | Description | Best for |
|-------------|-------------|----------|
| Completed worksheet | A filled-in document the student takes away | Planning, analysis, reflection modules |
| Practice output | A piece the student produced (a draft, a design, a calculation) | Skill-practice modules |
| Decision recorded | A choice the student has made and documented ("I will use X approach") | Strategy and planning modules |
| Self-assessment | A scored quiz or rubric the student applies to their own work | Knowledge and evaluation modules |
| Mini deliverable | A small finished artifact (a proposal section, a headline set, a spreadsheet model) | Project-based modules |
| Commitment statement | A written statement of intent ("By the end of this week I will...") | Habit and behavior modules |
| Peer share | Something the student posts to the course community | Community-based courses |

Use a mix of marker types across the course. A course with only quizzes feels academic. A course with only worksheets can feel repetitive.
